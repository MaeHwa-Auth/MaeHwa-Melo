# 큰 버그 수정 기록: 앨범 커버 미표시

- 날짜: 2026-10-11
- 발생 범위: 0.4.0 모듈화 이후 릴리스 앱의 Spotify 및 로컬 곡 커버
- 증상: 곡 목록, 재생 바, 지금 재생 패널에서 실제 커버 대신 MaeHwa 기본 이미지가 표시됨. Spotify 플레이리스트 커버는 표시되어 CDN 전체 차단과는 증상이 달랐음.
- 원인: 공통 트랙 커버 렌더러가 커버 URL을 CSS 사용자 정의 속성의 `background-image`로 전달하고 의사 요소에서 표시했음. 분리된 실제 릴리스 렌더링 경로에서 이 표시 방식이 실패했으며, Spotify 데이터와 로컬 커버 데이터가 저장 단계에서 모두 사라진 문제는 아니었음.
- 수정: `src/features/library/trackPresentation.ts`에서 트랙 커버를 실제 `<img>` 요소로 렌더링. 이미지 로드 실패 시 해당 이미지를 제거하고 기존 기본 커버가 보이도록 처리. 크기, 크롭, 페이드 전환은 기존 표시와 동일하게 유지.
- 확인: Windows NSIS 릴리스 빌드 및 TypeScript 빌드 성공. 사용자가 설치 후 Spotify와 로컬 파일 모두 커버 복구를 확인함.
- 교훈: API 응답이나 저장 데이터만 확인하지 말고, 실제 릴리스의 공통 렌더 경로까지 확인해야 함. 플레이리스트 커버와 트랙 커버가 서로 다른 렌더링 경로였음.

## 함께 수정한 좁은 창 사이드바

- 증상: 좁은 WebView에서 왼쪽 메뉴 글자는 숨겨져 아이콘만 남는데, 사이드바 너비는 확장 상태로 남는 경우가 있었음.
- 원인: `@media(max-width:640px)`의 `.sidebar` 너비 규칙보다 뒤에 선언된 `.workspace>.sidebar` 규칙이 더 높은 선택자 우선순위로 너비를 다시 적용했음. 결과적으로 아이콘 전용 스타일과 넓은 패널 너비가 동시에 나타남.
- 수정: 좁은 창에서 `.workspace>.sidebar`에도 60px 너비와 flex-basis를 명시해 우선순위 충돌을 해소. 축소 모드에서는 56px 버튼이 패널 안에 들어가도록 가로 패딩을 제거.
- 후속 수정(0.5.0): 위 너비 덮어쓰기만으로는 상태 불일치의 근본 원인을 제거하지 못했음. 미디어쿼리가 `.sidebar:not(.is-compact)`에 아이콘 전용 스타일을 적용하던 선택자 오류를 수정하고, 별도 너비 강제를 제거해 앱 상태와 화면 표현이 항상 일치하도록 함.
